# Merged Five-Branch Feel-WM + V7 + V7-F trainer

This is the VS Code / SSH training project for the architecture agreed in chat.

## Architecture locked in this code

The world-model visual state at each time is a stable post-Perceiver V7 latent packet:

- DINOv3: `16 x 256`
- ConvNeXt: `16 x 256`
- Utonia/PTv3 geometry: `16 x 256`
- WAFT/flow: `16 x 256`
- Concatenated: `Z_t = 64 x 256`

The 9 Feel-WM groups are exactly:

`G0=Z(t-3)`

`G1=FiLM_HL(Z(t-3), p_HL + Enc(a_HL,t))`

`G2=FiLM_HR(Z(t-3), p_HR + Enc(a_HR,t))`

`G3=Z(t-2)`

`G4=FiLM_FL(Z(t-2), p_FL + Enc(a_FL,t))`

`G5=FiLM_FR(Z(t-2), p_FR + Enc(a_FR,t))`

`G6=Z(t-1)`

`G7=Z(t)`

`G8=FiLM_Body(Z(t), p_body + Enc(a_body,t))`

**Important:** all four leg branches use the CURRENT rollout-step action `a_t`. The action is never changed to `a_(t-1)` or `a_(t-2)` merely because the terrain image is older. Only the terrain alignment is delayed.

World transformer capacity is the requested configuration:

- 8 layers
- 10 heads
- `d_model = 800` (80 dimensions/head; 768 cannot be divided by 10)
- FFN expansion ratio = 7, i.e. `800 -> 5600 -> 800`
- physical-time causal masking

Four independent latent heads predict `DINO_(t+1)`, `Conv_(t+1)`, `Geom_(t+1)`, and `Flow_(t+1)`. The predicted `64 x 256` visual state is fed back autoregressively.

The V7 decoder retains leg/body causal history encoders, temporally aligned terrain queries, leg fusion, 384-D global context, 768-D future dynamics state, contact/load/state heads, 1285-D per-leg force context, base V7 force head, and the V7-F horizon specialist.

## Why the trainer consumes post-Perceiver visual latents

This project intentionally trains the merged world/dynamics model on **stable post-Perceiver branch latents** rather than recomputing DINOv3/ConvNeXt/PTv3/WAFT inside every training iteration. It is the practical and stable interface for your existing V7 feature pipeline and avoids a moving/collapsing target when the network is asked to predict its own latent target.

Use your existing V7 preprocessing to persist each frame as four `16x256` branch blocks in fixed order: DINO, ConvNeXt, geometry, flow. The target future latents must be generated by the same frozen visual encoder/resampler stack.

## Data format

The loader reads a JSONL manifest. Each line is:

```json
{"path":"/absolute/path/shard_000.pt","index":0}
```

Each shard is saved as:

```python
torch.save({"samples": [sample0, sample1, ...]}, "shard_000.pt")
```

Each sample requires the following tensors:

- `z_window`: `[4,64,256]`
- `leg_hist_t`, `leg_hist_tm1`, `leg_hist_tm2`: `[4,T,24]`
- `body_hist_t`: `[T,18]`
- `body_action_seq`: `[K,4]`
- `leg_action_seq`: `[K,4,4]`, order `FL,FR,HL,HR`; these are the current actions for each rollout step
- `leg_query_features_seq`: `[K,4,24]`
- `future_action_seq`: `[K,36]`
- `physics_seq`: `[K,47]`
- `horizon_seq`: `[K,1]`
- `lowlevel_cmd_seq`, `err_seq`: `[K,4,3]`
- `jointbody_baseline_seq`: `[K,36]`, `jointbody_std`: `[36]`
- `tau_baseline_seq`: `[K,4,3]`, `tau_std`: `[3]`
- `force_baseline_seq`: `[K,4,3]`, `force_std`: `[3]`
- `target_z_seq`: `[K,64,256]`
- `target_contact_seq`: `[K,4]`
- `target_load_class_seq`: `[K,4]`
- `target_jointbody_seq`: `[K,36]`
- `target_tau_seq`: `[K,4,3]`
- `target_force_seq`: `[K,4,3]`
- `target_phase_seq`: `[K,4]`

The baseline/std tensors preserve V7's residual-prediction design instead of silently turning it into absolute regression.

## First server check

```bash
cd merged_feelwm_v7
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python smoke_test.py
```

The smoke test deliberately uses a tiny transformer configuration so it verifies every tensor path and backward pass quickly. Your YAML retains the full `800 / 10 heads / 8 layers / 7x FFN` architecture.

```bash
python scripts/make_dummy_data.py --out /tmp/wm_dummy
```

Put the printed manifests into a temporary copy of `configs/train_2x4080.yaml` and run a few steps.

## Real 2-GPU launch

Edit the three absolute paths in `configs/train_2x4080.yaml`, then:

```bash
chmod +x launch_2gpu.sh
./launch_2gpu.sh
```

Equivalent command:

```bash
torchrun --standalone --nproc_per_node=2 train.py --config configs/train_2x4080.yaml
```

This uses **DDP**, not `nn.DataParallel`.

## AMP and RTX 4080

The default is BF16 autocast + TF32. The trainer supports `bf16`, `fp16`, or `fp32`. The YAML starts at per-GPU batch size 1 with gradient accumulation because the requested 8-layer, 800-wide, 7x-FFN world transformer is large. Increase batch size only after checking actual VRAM use.

## Checkpoint / resume behavior

`latest.pt` is atomically replaced every `checkpoint_every_steps` and at the end of every epoch. It stores:

- model
- optimizer
- LR scheduler
- AMP scaler
- epoch/step
- RNG states
- resolved config

`resume: auto` automatically resumes `output_dir/checkpoints/latest.pt` after a disconnect/restart.

SIGINT/SIGTERM requests cause a checkpoint at the next safe optimizer-step boundary. A literal instantaneous power loss cannot write a new checkpoint after power disappears, so the maximum lost work is the interval since the last durable checkpoint.

## One temporal detail to set correctly

`history_shift_samples` controls how far the 100-Hz-style proprio history advances per world-model rollout step. For a 0.1 s world step on a 100 Hz history, use `10`. If you preprocess histories directly onto the same 10 Hz model grid, use `1`.
